SEO rewards **consistent basics** more than clever tricks. Use this checklist when you launch a page or refresh an important URL. Work top to bottom; stop when time runs out—partial progress still helps.

## 1. Clarify the page’s job

Every indexable URL should answer one primary intent:

- What query should this page rank for?
- What action should the visitor take next?

If you cannot answer in one sentence, rewrite the heading before you touch tags.

## 2. Title and meta description

- Unique title per URL (roughly under ~60 characters when possible).
- Description that summarizes benefit + proof (not keyword stuffing).
- Match the visible H1 to the promise in the title.

Generate draft tags with the [Meta Tag Generator](/developer-tools/meta-tag-generator), then edit for voice.

## 3. Crawl and index controls

- Confirm important pages are **not** blocked in robots.txt.
- Use noindex only for thin, private, or duplicate URLs.
- Keep a current XML sitemap of canonical URLs.

Create or refresh rules with the [Robots.txt Generator](/developer-tools/robots-generator) and list URLs with the [Sitemap Generator](/developer-tools/sitemap-generator).

## 4. On-page structure

- One H1; logical H2/H3 hierarchy.
- Descriptive internal links (avoid “click here”).
- Images with meaningful alt text when they convey information.
- Fast enough LCP on mobile—compress heavy heroes (see image optimization posts).

## 5. Quick technical sweep

Run a pass with the [Website SEO Audit](/developer-tools/website-seo-audit) mindset:

- Broken links on key templates
- Missing canonicals or conflicting duplicates
- Mixed http/https assets
- Thin pages that compete with stronger URLs

## 6. After publish

1. Inspect the live URL in Search Console (when available).
2. Request indexing only for priority pages—not every typo fix.
3. Re-check titles in the SERP preview after a week; rewrite weak CTR copy.

## What not to obsess over

- Exact keyword density
- Massive footer link farms
- Fake aggregate ratings in schema
- Buying links as a first growth lever

## Next steps

Complete items 1–3 on your homepage and one money page today. Then schedule a monthly audit so regressions do not silently undo the work.

## How to apply this without boiling the ocean

Pick one template (homepage, category, product, or article) and ship a complete pass:

1. Confirm the **primary URL** and title/description match search intent.
2. Fix **indexability** (robots, canonical, sitemap inclusion).
3. Improve **on-page clarity** (one H1, descriptive H2s, internal links to supporting pages).
4. Measure with Search Console or a crawl—not screenshots alone.

SEO work compounds when you document decisions. Keep a short note of what you changed and why. Revisit after indexing cycles instead of tweaking daily. Pair technical fixes with content that answers the query; markup and sitemaps cannot rescue a page with nothing useful to say.

If you are also experimenting with answer-engine visibility, keep claims factual and cite primary sources. Structured data should reflect visible content—never invent FAQs or ratings that users cannot see.

## Step-by-step approach

1. **Clarify the outcome** — what does “finished” look like (file delivered, page indexed, bug fixed, draft approved)?
2. **Gather inputs** — source files, URLs, error messages, constraints, and deadlines.
3. **Apply the smallest change** that could work; avoid parallel experiments that hide the cause.
4. **Validate** with a second device, a clean browser profile, or a fresh export.
5. **Document the winning path** in three bullets so next time is faster.

## Common mistakes (and quick fixes)

- **Skipping the preview** — always open the final artifact before sharing.
- **Optimizing the wrong metric** — file size, rankings, or speed only matter relative to the real goal.
- **One giant edit** — smaller passes are easier to reverse when something breaks.
- **Ignoring mobile** — many PDF, SEO, and UI issues only appear on a phone viewport.
- **Trusting defaults** — export quality, crawl rules, and model temperature are not universal.

When something fails twice, change the method instead of retrying the same click pattern. Capture a screenshot or error string; future-you (or a teammate) will thank you.
